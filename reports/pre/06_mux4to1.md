# 실험 전 레포트: 4:1 멀티플렉서

작성일 2026-09-19.

## 목적과 예상값

4비트 데이터 입력 `i[3:0]` 중 2비트 선택선 `s[1:0]`이 가리키는 비트를 단일 출력선 `z`로 라우팅합니다. top은 `mux_4x1`입니다. 인덱스 역산식 `z = i[3-s]`를 적용하여 선택선 값에 따른 입출력 경로를 매핑합니다.

| s[1:0] | 선택 비트 | i = 1000 (8) 일 때 z | i = 0001 (1) 일 때 z |
|---|---|---:|---:|
| 00 | i[3] | 1 | 0 |
| 01 | i[2] | 0 | 0 |
| 10 | i[1] | 0 | 0 |
| 11 | i[0] | 0 | 1 |

## 환경과 입력 파일

Windows, Git 2.55.0, VS Code 1.136.1, XSim 2026.1을 사용했습니다. 공개 템플릿의 커밋 `740aef5`를 공백이 있는 별도 폴더에 새로 clone했습니다. `LAB1.code-workspace`는 `vivado_2026_1/06_mux4to1`를 PROJECT, `common`을 COMMON으로 연결합니다.

[RTL](../../src/mux_4x1.v), [TB](../../sim/tb_mux_4x1.sv), [XDC](../../constraints/mux_4x1.xdc)를 사용했습니다. TB top은 `tb_mux_4x1`이며 루프 변수 0부터 63까지 10ns 간격으로 인가하여 64가지 조합을 검사합니다. 기대값과 실제 출력을 비교하여 64건 완료 시 PASS를 출력하고 640ns에 종료합니다.

## 실행과 관찰

VS Code 새 창에서 workspace를 열고 slang-server와 VaporView를 활성화했습니다. 저장 후 Terminal → Run Task...의 Check tools, Simulate를 실행하고 Open waveform으로 VCD를 열었습니다. `i,s,z`를 추가하고 Zoom to Fit와 ns 단위를 선택했습니다.

실제 [VS Code 작업 실행 로그](../../evidence/06/vscode/simulation.txt)에서 `LAB1_PASS mux_4x1 cases=64`과 640ns 종료를 확인했습니다.

| 구간(ns) | i (hex) | s | z | 해석 |
|---|---|---|---|---|
| 0–40 | 0 | 00\~11 | 0 | 데이터가 0이므로 선택선 무관 z=0 |
| 320–330 | 8 (1000) | 00 | 1 | s=00일 때 i[3] 선택되어 z=1 |
| 330–360 | 8 (1000) | 01\~11 | 0 | 0인 입력선이 선택되어 z=0 |
| 630–640 | F (1111) | 11 | 1 | 모든 데이터 1 조건에서 z=1 |

전환 순간 대신 구간 중간에서 커서를 읽었습니다. 파형만 눈으로 맞아 보이는 것에 더해 자동 비교 64건과 정상 종료를 함께 확인했습니다.

## 보드 실험 계획

KEY1\~4(i[3:0]), DIP1\~2(s[1:0]), LED1(z), LVCMOS33입니다. Vivado에서 같은 TB를 실행한 다음 bit를 생성하고 보드에 다운로드합니다. KEY1(i[3])만 누른 상태에서 스위치 s를 00으로 두었을 때 LED1이 켜지고, 다른 스위치 위치에서는 꺼지는 선택 동작을 사진·영상으로 담을 계획입니다.
